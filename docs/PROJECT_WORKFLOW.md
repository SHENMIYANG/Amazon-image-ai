# 项目当前工作流

这份文档只描述当前代码里的真实流程，不讨论已经废弃或半废弃的旧方案。

## 一句话概括

这是一个“先做产品理解和图片策略，再做 AI 生图”的亚马逊商品图工作台。

## 4 个阶段

### 1. 用户输入

输入内容包括：

- 产品主图
- 辅助参考图
- Listing 信息
- 补充信息
- 销售国家 / 生成语言
- 品牌主色 / 字体偏好
- 出图复杂度
- 需要生成的图片类型和张数

### 2. 产品理解

由 `/api/agent-analyze` 完成。

这一阶段的目标不是直接生成 Prompt，而是先形成一份共享的产品理解：

- 产品是什么
- 主图里什么最可信
- 参考图能补充什么
- 这次到底要生成哪些图片任务

输出重点：

- `productBlueprint`
- `imagePlans[]`

### 3. 策略确认

运营查看中文策略正文 `strategyContent`。

如果需要：

- 改某一张图的中文策略
- 保存该图的英文执行稿

这里的核心原则是：

> 中文策略是运营看到的唯一真相；英文执行稿是它的执行翻译版本。

### 4. AI 生图

由 `/api/generate` 完成。

这一层的职责是执行，不应该重新做业务规划。

也就是说，Generate 最终拿到的应该是：

- 当前产品真相
- 当前图片任务
- 当前策略正文的执行版
- 参考图

而不是重新从 Listing 全量内容里再思考一遍。

## 当前最重要的设计原则

### 1. 主图优先级最高

主图是产品真实性最高依据。

辅助参考图只能补充：

- 角度
- 结构细节
- 使用方式
- 版式灵感
- 风格氛围

不能覆盖主图定义的产品本体。

### 2. 策略层做决策，执行层不再二次规划

`agent-analyze` 决定：

- 这张图应该表达什么
- 重点卖点是什么
- 允许什么文案
- 禁止什么错误

`generate` 负责：

- 把当前策略交给图片模型
- 结合参考图执行

### 3. 每张图职责不同，避免重复卖点

如果用户选择：

- 1 张主图
- 3 张卖点图

那策略层应负责拆分 3 张卖点图的不同职责，而不是三张图都重复同一个卖点。

### 4. 复杂度是执行强度，不是固定模板

复杂度当前分为：

- `L1`
- `L2`
- `L3`

更合理的使用方式是：

- 影响信息密度
- 影响视觉层级
- 影响版式复杂度
- 影响文案多少

而不是简单把某个模板写死。

## 当前代码中的主要接口

- `/api/upload`
- `/api/agent-analyze`
- `/api/prompt-preview`
- `/api/generate`
- `/api/health`

## 推荐维护方向

后续继续改代码时，优先保证：

1. 主流程不变
2. 中文策略和英文执行稿一一对应
3. Generate 不要偷偷新增业务语义
4. 非主图卖点不要重复
5. 参考图优先级规则保持稳定
